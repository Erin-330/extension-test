# 기능명세서 → 페이지 MD 변환 템플릿

기능명세서(이미지 또는 텍스트)를 받아 페이지 MD를 작성할 때 이 파일을 먼저 읽고 아래 구조를 따른다.  
각 섹션 옆에 `(필수)` / `(조건부)` 표시가 있다. 조건부 섹션은 해당 기능이 없으면 생략한다.

---

## 파일명 규칙

저장 위치: **`.claude/pages/`**

| 대상 | 파일명 |
|------|--------|
| 단일 페이지 | `.claude/pages/[페이지명].md` (예: `login.md`, `profile.md`) |
| UI 레이아웃 중심 | `.claude/pages/[페이지명]-ui-layout.md` |
| Rive 구현 중심 | `.claude/pages/[페이지명]-rive.md` 또는 `-rive-graph.md` |
| 복합 기능 페이지 | 레이아웃 MD + Rive MD 분리 작성 |

---

## 기능명세서 이미지에서 추출해야 할 정보

기능명세서 이미지가 프롬프트로 오면 아래 항목을 이미지에서 읽어 MD를 작성한다.

| 명세서 섹션 | MD 섹션 | 추출 포인트 |
|------------|---------|------------|
| 목적 | 개요 | 1줄 요약 |
| 주요 기능 | 개요 | 불릿 → 표 또는 목록 |
| 상세 요구사항 | 레이아웃 + 컴포넌트 상세 + 상태별 표시 | 화면 구조, 조건, 규칙 |
| 예외 및 정책 | 상태별 표시 + 각 섹션 규칙 | 에러·빈 상태·제한 조건 |

## 작성 원칙

1. **간결하게** — 코드로 구현 가능한 자명한 내용은 적지 않는다. "버튼이 있다" 대신 동작 조건·규칙만 명시.
2. **Rive 필수 경고** — Rive 파일이 사용되는 섹션은 반드시 `> ⚠️` 경고 박스를 달고 CDN URL, 아트보드명, State Machine명을 명시한다.
3. **API는 실제 엔드포인트** — 추측하지 말고 명세서에 명시된 것만 적는다. 없으면 섹션 생략.
4. **데이터 필드명은 실제 키** — camelCase/PascalCase 등 실제 API 응답 키 그대로 사용한다.
5. **ASCII 레이아웃** — 화면 구조는 항상 ASCII 다이어그램으로 표현한다. 위→아래 순서로 배치.
6. **CLAUDE.md 업데이트** — 새 MD 파일을 만들면 CLAUDE.md의 "Spec Files 읽기 규칙" 섹션에 해당 HTML과 MD 파일의 연결 규칙을 추가한다.
